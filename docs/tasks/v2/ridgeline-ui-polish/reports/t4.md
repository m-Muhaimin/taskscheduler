## Deviations from the brief

1. **`results-band.tsx` eyebrow NOT swapped to `<Eyebrow>`.** Its markup is `font-mono text-[12px] uppercase tracking-[0.12em] mb-4` + inline `style={{ color: "var(--band-muted)" }}` — it does not use the `text-ink-muted` pattern the swap targets, because it sits on the dark `.band`. The shared `Eyebrow` (T1's file, read-only for this task) hardcodes `text-ink-muted` and accepts no color prop. On the dark band in light theme `--ink-muted` (#736a5b) computes ≈3.3:1 against `--band-bg` (#1c1a16), versus the design's `--band-muted` (#b8ad99) at ≈7.8:1 — swapping would visibly break the band label and violate "both themes must look right". Keeping the token-styled (`var(--band-muted)`) label; the results band's bottom footnote (same band-muted color) was already out of pattern (no uppercase) and stays.
2. **FAQ question title left at `text-[18px]`.** `<span className="text-[18px] font-medium leading-snug">` is the accordion question — title-family (controls row titles 16px, how-it-works step titles 24px), not body copy. The brief's deliverable 2 names only "results-band stat text and handoff/controls bodies" as 18→17 targets, and none of those were 18px in the current tree (handoff/controls bodies were already 17px; results-band has no 18px text). If the reviewer classifies FAQ questions as body, it's a one-value change.
3. **`site-footer.tsx` delta is `py-8` → `py-16 md:py-20`** (not `py-8` → smaller step): deliverable 5 says "align vertical padding to the new section rhythm (py-16 md:py-20 max)" — read the parenthetical as the target value so the last band ends on the same beat as sections.

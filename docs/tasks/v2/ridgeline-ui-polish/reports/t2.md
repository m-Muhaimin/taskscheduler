## Key implementation decisions

### Sidebar
- `SidebarNav` is the shared inner content (brand, nav groups, identity, sign out) extracted from `nav-rail.tsx` unchanged in look/behavior. Nav links call `onNavigate?.()` first on click; passed as a no-op on desktop, wired to `onClose` in the drawer. Sign out also calls `onNavigate?.()` before `signOut()` so the drawer closes on the route change.
- `DesktopSidebar` renders the exact aside spec: `hidden md:flex w-60 shrink-0 flex-col border-r border-border px-4 py-5 bg-surface sticky top-0 h-screen overflow-hidden self-start`. Per locked decision #4, the nav region itself is `overflow-y-auto` (with `-mx-4 px-4` so the scrollbar sits flush with the panel edge and internal scroll doesn't conflict with the rail's `overflow-hidden`); identity block stays pinned via `mt-auto`.
- `MobileSidebar` = `Drawer` with `label="Navigation"` + `SidebarNav onNavigate={onClose}` — closes the drawer when a nav link (or brand link) is clicked.

### Drawer a11y contract (`components/ui/drawer.tsx`)
- `role="dialog"`, `aria-modal="true"`, `aria-label={label}`, `tabIndex={-1}` on the panel; `id="mobile-nav"` matched by the hamburger's `aria-controls`.
- Focus: saves `document.activeElement` on open, `panel.focus()` on the container, restores focus to the saved trigger in the effect cleanup on close. This is what returns focus to the hamburger.
- Focus trap: `onKeyDown` on the panel intercepts Tab/Shift+Tab, collects `a[href], button, input, [tabindex]:not([tabindex="-1"])` inside the panel (excluding `[disabled]` and anything `aria-hidden`/inside `[aria-hidden="true"]`), cycles first/last; panics safely to `preventDefault` if nothing is focusable.
- ESC: `window` keydown listener while open → `onClose` (with `stopPropagation` so the drawer is the single consumer).
- Scroll lock: T1 `useLockBodyScroll(open)` — restores the exact prior `body.style.overflow` on unlock/unmount.
- Reduced motion: T1 `useReducedMotion()` — when true the panel renders in place with **no transform and no animation classes** (no slide, no fade). Slide is `-translate-x-full → translate-x-0` with `transition-transform duration-[260ms]` + `cubic-bezier(0.16,1,0.3,1)`; overlay fades via `transition-opacity duration-[260ms]`. The `entered` state is flipped via `requestAnimationFrame` on open so the enter transition actually runs (and resets to off-state) on every open.
- Unmount immediately on close (no exit animation), as the brief allows and documents.

### A11y decisions beyond the literal brief
- Overlay is a `<button aria-hidden="true">` **with `tabIndex={-1}`** — the brief specified the button + `aria-hidden`, but an `aria-hidden` element must not be keyboard-focusable; `tabIndex={-1}` keeps it clickable while removing it from the tab order (it is also outside the panel so the trap never routes to it).
- Added a dedicated close button (X, `aria-label="Close navigation"`) in the panel's top-right — the T2 verification expects a close affordance beyond overlay/ESC ("overlay click, ESC, close all close it"), and master doc #5 lists "ESC / overlay-click / close button". It is inside the panel, so it participates in the focus trap.
- `outline-none` on the panel container: the container takes programmatic focus once, so the global `:focus-visible` outline would otherwise paint a ring around the whole panel; real interactive controls inside retain their own focus-visible styles.
- Hamburger: followed the brief exactly (`aria-haspopup="dialog"` + `aria-controls`). `aria-expanded` was intentionally **not** added: TopBar does not own the open state (the shell does, per the brief's prop contract `{ onMenu }`), so an `aria-expanded` would be a hardcoded lie; the dialog + aria-controls wiring satisfies the a11y requirement for a mobile slide-over where the trigger lives outside the conversation subtree.
- Drawer panel gets `px-4 py-5` (not in the literal brief's class list) so the shared `SidebarNav` content — which carries no own padding, matching the DesktopSidebar aside — renders flush-consistent in both hosts. Flagging as a deliberate deviation.

## Deviations from the brief
1. `px-4 py-5` added to the drawer panel (see above) so sidebar content isn't edge-to-edge on mobile. No other markup deviations.
2. `type="button"` added to the TopBar hamburger (defensive; it is not inside a form so it was harmless, but the button now has an `onClick` and explicit type is the convention in this codebase).
3. Close button added to the drawer (matches T2 verification + master doc #5, see a11y decisions).
